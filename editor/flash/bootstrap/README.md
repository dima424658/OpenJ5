# Сборка загрузчика C509‑L

`c509/bootstrap.c` реализует точку входа, определение разводки платы, UART, низкоуровневые операции Flash и EEPROM, однопроводное чтение, приём кадров и обработчики команд `0x10–0x1B`. Приёмник проверяет размеры блоков до обращения к памяти. [Разбор оригинального загрузчика](../../../analysis/combiloader-2.18/README.md#код-исполняемый-в-эбу)

Сборка из корня репозитория требует Rust, Make, Python 3 и SDCC 4.6 с инструментами `sdas8051` и `sdld` в `PATH`.

```sh
make -C editor/flash
```

Make сначала собирает бутстрап в `editor/target/bootstrap`, затем Cargo встраивает кадры в `editor/target/release/janvar-flash`. Цель `make -C editor/flash desktop` собирает Editor с тем же встроенным бутстрапом. Для сборки только бутстрапа используйте `make -C editor/flash bootstrap`, для тестов — `make -C editor/flash test`. При прямом запуске Cargo скрипт сборки генерирует кадры в каталоге Cargo.

Образ занимает диапазон `0xF400–0xFF04`, 2821 байт из 3072 байт XRAM. Скрипт проверяет, что код помещается в XRAM и переменные компилятора расположены ниже стека. [Руководство C509‑L, таблица 3-1](https://www.infineon.com/assets/row/public/documents/10/53/m509.pdf#page=28)

Для запуска достаточно исполняемого файла. Перед открытием порта утилита проверяет SHA‑256 встроенного бутстрапа `a043ab3c2227e84ca6c3f875091ab4747be81534533bf8d81dc408f4b25ad789`. После стендовой проверки новой версии обновите размер кадров и контрольную сумму в `../src/session.rs`, если они изменились.

В модели памяти C-обработчики вернули 2078 побайтно совпадающих ответов из восьми стендовых захватов. В эмуляторе 8051 проверены чтение и программирование Flash, последовательности команд стирания для прямого и обратного порядка битов, отказ при неверной длине кадра и выход по `0x10` с восстановлением указателя стека. Для проверки кадров использован моделируемый UART.

В предыдущей сборке с низкоуровневыми ассемблерными процедурами ЭБУ на стенде macOS с FTDI подтвердил 188 кадров загрузки, вернул флаги `00` и отдал 512 байт EEPROM за четыре блока. Дамп сохранён в `eeprom-c.eep`. Тем же C-бутстрапом прочитаны 65 536 байт Flash за 512 блоков. Файл `firmware-c.bin` побайтно совпал со штатным дампом `firmware.bin`, встроенная контрольная сумма — `8B3C`. На том же блоке ЭБУ подтвердил стирание перед записью, запись всех 512 блоков из `firmware-c.bin` и завершение программирования. После перезапуска контрольное чтение подтвердило побайтное совпадение всех 65 536 байт с записанным файлом. Отдельный стендовый прогон подтвердил очистку всех 65 536 байт Flash и всех 512 байт EEPROM до `FF`. После записи резервных копий и перезапуска обе памяти побайтно совпали с исходными дампами.

В первой сборке целиком на C ЭБУ подтвердил 192 кадра загрузки. За одну сессию прочитаны 512 байт EEPROM и 65 536 байт Flash с побайтным совпадением с обоими резервными дампами. Запись, стирание и однопроводной обмен в этой сборке на ЭБУ ещё не проверены.

После объединения блочных операций Flash и упрощения циклов EEPROM размер образа уменьшился на 108 байт, а количество кадров загрузки — со 192 до 185. В uCsim обработчик чтения последнего блока Flash из 128 байт выполнился за 21 432 такта вместо 65 748. Замер охватывает обработку команды внутри ЭБУ.

Однобитные статусы операций и выбор банка, а также обход таблицы зеркальных идентификаторов Flash сократили образ ещё на 96 байт. Для загрузки текущей сборки нужно 179 кадров.

Текущая сборка размером 2821 байт прошла стендовый прогон на macOS с FTDI и флагами ЭБУ `00`. Отдельное чтение после очистки подтвердило `FF` во всех 65 536 байтах Flash и 512 байтах EEPROM. После восстановления и перезапуска оба дампа побайтно совпали с исходными резервными копиями.
