# Карты калибровок J5

Образ BIN содержит код и данные ЭБУ. Карта редактора описывает расположение параметров и способ их отображения для конкретной версии ПО. Документация ChipTuningPRO описывает адреса, таблицы и настройки масштабирования, а модуль Январь показывает дерево параметров и графики. Детали двоичной сериализации CTM в документации разработчика не найдены. [ChipTuningPRO 4](https://almisoft.ru/ctpro4.htm) · [Модуль с примерами окон Январь 5.1](https://almisoft.ru/ctpro_base.htm) · [Копия руководства ChipTuningPRO](https://ru.scribd.com/document/1065366952/ChipTunerPro-%D0%B8%D0%BD%D1%81%D1%82%D1%80%D1%83%D0%BA%D1%86%D0%B8%D1%8F)

## Строковые поля CTM

Внутри контейнера есть читаемые строки с однобайтовой длиной. Заголовки обеих сборок содержат шесть полей. У `0738` первое находится по `0x00D0`, шаг `0x41`. У `0923` первое по `0x00D6`, шаг `0x40`. Первый байт поля задаёт число байтов текста, за текстом до конца поля идут нули. В этих полях хранятся имена параметров паспорта ЭБУ, например `VehicleManufacturerECUHardwareNumber`, `SystemNameOrEngineType` и `ProgrammingDate `.

В записях встречаются подписи Windows-1251 с таким же префиксом длины. Например, в L19 сборки `0923` по `0x12F7F` стоит `0x18`, за ним идут 24 байта подписи «Добавочное время впрыска». По `0x12F9F` начинается отдельное текстовое поле `!040-60BC-60BD-0.093`. В I02 та же подпись начинается с префикса по `0x104F8`. У нескольких записей два поля с тегами идут подряд с шагом `0x100`, например в L19 по `0x59F7` и `0x5AF7`. Длина задаётся первым байтом поля, остаток его 256-байтового слота заполнен нулями.

Регулярным поиском найдено 103 тега в каждой карте L19 и 77 в каждой карте I02 сборки `0738`. У `0923` соответственно 105 и 79. Это число строк, начинающихся с `!` и подходящих под синтаксис ниже. Несколько таких строк могут относиться к одной записи. Значительная часть отличий `_f` приходится на замену `-30` на `-40` в тегах с `613C`. В части тегов L19 `0923` также меняется регистр `C`. Значение суффикса тега ещё требует подтверждения. Компоненты `613C` и `7208` совпадают с адресами, к которым обращаются обе прошивки. Смысл каждого компонента тега нужно проверять по записи и коду, который использует соответствующий адрес.

В `0738` адреса порогов `0x60C7` и `0x60C8` отсутствуют в прямом представлении как 16-битные слова. В `0923` два вхождения байтов `60 C8` находятся вне сопоставленных записей вентилятора.

Чтение обнаруженных полей из корня проекта. Смещения в выводе указывают на байт длины строки.

```python
import re
from pathlib import Path

for path in sorted(Path("bins").glob("*.j5")):
    data = path.read_bytes()
    tags = []
    for match in re.finditer(rb"![0-9]{3}(?:-[0-9A-Fa-f.]+)+", data):
        offset = match.start() - 1
        if offset >= 0 and data[offset] == len(match.group()):
            tags.append((offset, match.group().decode("ascii")))
    print(path.name, len(tags))
    for offset, tag in tags:
        print(f"  0x{offset:05X} {tag}")
```

## Дерево записей CTM

Обе сборки читаются последовательно от первой записи до конца файла. Смещения ниже относятся к началу записи. Тело следует за фиксированным заголовком, его длина хранится в последних двух байтах заголовка как `uint16le`. Перед длиной идут байты глубины в дереве и типа. У записей с телом первые четыре байта тела идентифицируют параметр.

| Сборка | Начало дерева | Размер заголовка | Глубина | Тип | Длина тела | Записей L19 / I02 |
|---|---:|---:|---:|---:|---:|---:|
| `0738` | `0x02EA` | `0x45` | `+0x41` | `+0x42` | `+0x43` | 366 / 299 |
| `0923` | `0x02E8` | `0x4C` | `+0x48` | `+0x49` | `+0x4A` | 368 / 299 |

| Тип | Наблюдаемый вид | Длина тела `0738` / `0923` | Число записей в L19 `0738` / I02 `0738` |
|---|---|---|---:|
| `0` | Папка | `0x0000` / `0x0000` | 49 / 44 |
| `1` | Одномерная кривая | `0x01AE` / `0x018F` | 74 / 51 |
| `2` | Двумерная таблица | `0x02E2` / `0x02C2` | 38 / 30 |
| `3` | Скаляр | `0x0065` / `0x004A` | 202 / 172 |
| `4` | Группа битовых масок | `0x1286` / `0x123E` | 3 / 2 |

У всех параметров `0738` есть ровно одно соответствие по типу и четырёхбайтовому идентификатору в `0923` для того же семейства. У L19 это 317 параметров, у I02 — 255. В L19 `0923` есть два дополнительных скаляра с идентификаторами `123CF7B3` и `E80C525B`. Их имена и адреса пока неизвестны. Варианты `_f` сохраняют состав дерева и идентификаторы.

В `0738` второе 32-битное слово тела декодируется как `uint32le(field) ^ 0xD366019C`. У 313 параметров L19 и 251 параметра I02 результат находится в пределах BIN. У четырёх кривых результат представляет специальный адрес, разрешаемый по коду прошивки. В `0923` для групп битовых масок второе слово тела содержит прямой адрес `uint32le`. Это подтверждается адресами `0x6051` и `0x60DA` в обоих семействах и `0x5FAC` в L19. Прямое чтение адресов кривых, таблиц и скаляров `0923` ещё не восстановлено.

Библиотека редактора читает обе сборки через `Catalog::parse()`. Для `0923` метод `Catalog::with_reference()` сверяет идентификаторы, типы, размеры и позиции битов с подходящей картой `0738`. Из неё берутся имена, недостающие адреса и параметры декодирования. Размеры, теги и имеющиеся подписи единиц берутся из самой `0923`. [Реализация чтения J5](../editor/src/j5.rs)

## Читаемые поля записей 0923

Смещения в таблице отсчитываются **от тела записи**, сразу после её заголовка размером `0x4C` у `0923` и `0x45` у `0738`. Строки начинаются с байта длины, текст читается в Windows-1251.

| Поле | Тип данных | `0923` | `0738` |
|---|---|---:|---:|
| Число отсчётов кривой | `uint16le` | `+0x1E` | `+0x152` |
| Тег оси кривой | Слот 256 байт | `+0x8D` | `+0x52` |
| Размеры таблицы | Два `uint8` в `0923`, два `uint16le` в `0738` | `+0x1E`, `+0x20` | `+0x273`, `+0x277` |
| Теги двух осей таблицы | Два слота по 256 байт | `+0xC0`, `+0x1C0` | `+0x73`, `+0x173` |
| Единицы скаляра | Строка с префиксом длины | `+0x38` | `+0x10` |

Размеры совпали для всех 125 кривых и 68 таблиц, сопоставленных между обычными картами. Теги двумерных таблиц тоже совпали. Две кривые, добавочное время впрыска и время накопления зажигания, в `0923` содержат `!040-60BC-60BD-0.093`, у соответствующих записей `0738` этот строковый слот пуст. У двух скаляров `0923` обрезает подпись единиц до 15 байт. У дополнительных скаляров L19 `123CF7B3` и `E80C525B` напрямую читаются единицы `об/мин`. Их имена и адреса пока неизвестны.

## Специальные адреса и код редактора

В обеих предоставленных DLL экспорт `ResolveAddress` распознаёт специальные адреса как отрицательные 32-битные значения. Статический разбор выполнен для `ctps.dll` сборки `0738` с SHA-256 `500f8698f8cf135efc2e90b05194c65beebb53f6c4d978521b3e2969debe411e` и `Ctps.dll` сборки `0923` с SHA-256 `1480a1f7eb8dce687fa709ceac972348383af0de93547932f98f3f8a4801a308`. Виртуальные адреса экспорта соответственно `0x40A994` и `0x405828` при базе PE `0x400000`.

| Значение | Назначение | Разрешение по BIN |
|---|---|---|
| `0xFFFFFF96` | Тарировка ДМРВ | Найти в коде `93 C3 C2 AF 25 ?? C5 F0 05`. Два байта перед совпадением задают начало таблицы в big-endian. Длина — 256 байт. В L19 это `[0x99B9, 0x9AB9)`, в I02 — `[0x46BB, 0x47BB)` |
| `0xFFFFFC0E`, `0xFFFFFC0D`, `0xFFFFFC0C` | Максимальное время работы стартера, обороты отключения и время работы после превышения порога | Поиск `SMSSwS` в BIN от `0x4000` до `0xFFF0`. База данных на 6 байт после маркера, смещения кривых `0x00`, `0x27` и `0x4E`. Маркер отсутствует в штатных L19 и I02 проекта |

В штатных образах после `MOV DPTR,#0x99B9` или `MOV DPTR,#0x46BB` стоит сам шаблон, начинающийся с `MOVC A,@A+DPTR`. Это дополнительно подтверждает адрес чтения таблицы ДМРВ. В библиотеке редактора `Entry::numeric()` разрешает специальный адрес по переданному образу BIN. [Реализация разрешения адресов](../editor/src/firmware/mapped.rs)

Предоставленный `Ctp.exe` сборки `0923` имеет компоновку с большой нефайловой секцией кода и отдельной входной секцией. В статическом анализе виден входной модуль, а чтение непрозрачных полей CTM в основном коде пока не прослежено. DLL дала обработчики специальных адресов и осей.

## Флаги комплектации и диагностические маски

В конце заголовка записей типа `4` указана длина тела. От начала тела по `+0x04` лежат восемь 32-битных little-endian адресов байтов маски. В `0738` первый адрес декодируется через XOR с `0xD366019C`. Остальные адреса записаны напрямую. В `0923` напрямую записаны все восемь. Значение `0xFFFFFFFF` обозначает пустую позицию.

По `+0x2C` идут восемь строковых слотов заголовков секций, за ними 64 слота подписей битов в порядке от младшего к старшему. Ширина слота `0x41` в `0738` и `0x40` в `0923`. В обеих сборках бит `0x6051.0` назван «Датчик концентрации кислорода», бит `0x60DA.7` — «Ошибка ПЗУ». Оба семейства содержат флаги комплектации и маску ошибок. В L19 также есть маска драйверной диагностики. [Редактирование флагов в CTP](ctp321.pdf#page=8)

## Скалярные записи CTM

В предыдущем проходе была выделена подгруппа скаляров с уровнем вложенности `3`. Смещения отсчитываются от байта длины имени.

| Смещение | Поле |
|---|---|
| `+0x00` | 64-байтовый слот имени. Однобайтовая длина, текст Windows-1251, нули до конца слота |
| `+0x41` | Маркер `03 03 65 00` |
| `+0x45` | Четырёхбайтовый признак записи, пригодный для сопоставления между сборками |
| `+0x49` | Адрес в BIN, `uint32le(field) ^ 0xD366019C` |
| `+0x90`, `+0x98` | Два числа IEEE 754 binary64 little-endian. У обоих порогов это `1.0` и `40.0`, что согласуется с подтверждённым преобразованием `T [°C] = raw − 40`. Общая семантика чисел для других типов ещё проверяется |

Размер скаляра с заголовком составляет `0xAA`. На уровне вложенности `3` находятся 96 скаляров в L19 и 67 в I02. Для четырёх записей вентилятора адреса дополнительно подтверждаются кодом `MOVC` в штатных прошивках, а для двух порогов также побайтовым сравнением изменённых BIN.

| Запись | Начало в L19 0738 | Начало в I02 0738 | Признак записи | Адрес в BIN |
|---|---:|---:|---|---:|
| Температура включения вентилятора | `0x153A3` | `0x12BE1` | `03 D9 CA 09` | `0x60C8` |
| Температура выключения вентилятора | `0x1544D` | `0x12C8B` | `CE F5 66 CE` | `0x60C7` |
| Задержка включения вентилятора | `0x154F7` | `0x12D35` | `7D 07 4C EF` | `0x60EE` |
| Смещение РХХ при включении вентилятора | `0x155A1` | `0x12DDF` | `F6 90 F0 6C` | `0x60ED` |

В `0923` те же признаки идут после маркера `03 03 4A 00`. У каждой из 96 записей L19 и 67 записей I02 найдено ровно одно соответствие, в обеих парах файлов. Например, признаки двух температур находятся в L19 `0923` по `0x14302` и `0x14398`, в I02 по `0x11C6B` и `0x11D01`. Представление полей после этих признаков в `0923` другое. Адреса для этих записей пока можно получить сопоставлением с `0738`.

## Кривые и таблицы в 0738

У кривых число отсчётов хранится по `+0x197` как `uint16le`. В картах встречаются размеры 5, 16, 32, 39, 40, 64, 101 и 256. У двумерных таблиц число точек осей лежит в `uint16le` по `+0x2B8` и `+0x2BC`. Во всех 38 таблицах L19 и 30 таблицах I02 оба значения равны 16. Теги осей находятся в строковых слотах по `+0xB8` и `+0x1B8`.

| Калибровка | Размер по карте | Адрес в BIN обеих прошивок | Наблюдение |
|---|---|---|---|
| УОЗ для экономичного режима | `16 × 16` | `0x6AC8` | Оси в карте подписаны как обороты и цикловое наполнение. Теги `!002-613C-30` и `!004-6064-6066` |
| Базовое цикловое наполнение | `16 × 16` | `0x75EF` | Оси подписаны как обороты и положение дросселя. Второй тег `!006-7208` |
| Желаемые обороты | 39 точек | `0x6F56` | Входная ось подписана как температура |

Для первых двух таблиц и кривой желаемых оборотов адреса совпали с чтениями из кода обеих прошивок. Порядок ячеек и расчёт сырого результата описаны в [разборе прошивки](firmware.md#чтение-калибровочных-таблиц). Масштабирование и знаковость значений следует проверять для каждого семейства параметров.

## Контрольная ячейка экономичного УОЗ

В редакторе `0738` изменена одна ячейка таблицы УОЗ при `720 об/мин` и `72 мг/цикл`, с `21,0` до `−25,5` градуса поворота коленвала. Оба значения осей стоят на втором месте. В экспериментальном BIN ячейка по `0x6AD9` изменилась с `0x2A` на `0xCD`. Это `0x6AC8 + 1 * 16 + 1`. Как знаковые байты в дополнительном коде, исходное и новое значения равны `42` и `−51`, что подтверждает масштаб редактора `УОЗ = int8(raw) × 0,5°`. Для редактора это поверхность с двумя входными осями и УОЗ по вертикали. Порядок хранения подтверждён кодом C509 и этим опытом.

Экспорт `ResolveSpecial` находится по `0x408BFC` у `0738` и по `0x404294` у `0923`. Ветви для тегов УОЗ строят оси из данных прошивки. Для этой штатной L19 результаты воспроизводятся так.

- Тег `!002-613C-30` задаёт источник `0x613C` и множитель `30 об/мин`. Редактор перебирает байты квантования. Он принимает переход, когда текущий байт отличается от следующего и равен нулю или достиг `16 × число уже принятых точек`. Индекс принятого байта умножается на 30. В L19 первые три точки — `600`, `720`, `840 об/мин`.
- Для тега `!004-6064-6066` берётся целая часть `uint16le(BIN[0x6064:0x6066]) / 6`. Это минимум `40 мг/цикл`. Шаг получается округлением `256 / (6 × BIN[0x6066] / 8) × 16`. В L19 байт `0xAB` даёт шаг `32 мг/цикл`. Первые три точки — `40`, `72`, `104 мг/цикл`.

В обычных картах обоих семейств и обеих сборок тег оборотов равен `!002-613C-30`. Во всех четырёх картах `_f` он равен `!002-613C-40`. По адресу `0x623C` в штатных BIN L19 и I02 лежит ряд из 16 little-endian слов `600, 720, 840, 990, 1170, 1380, 1650, 1950, 2310, 2730, 3210, 3840, 4530, 5370, 6360, 7500`. Редактор в `editor/` использует этот ряд из BIN и показывает тег загруженной карты в свойствах.

Знаковое представление выше описывает редактор и сохранённый BIN. В штатной процедуре интерполяции сырые байты смешиваются как беззнаковые числа. [Проверка перехода через ноль в C509](firmware.md#чтение-калибровочных-таблиц)

Справка CTP 3.21 указывает, что имя загруженной карты отображается в строке состояния, а команда F6 экспортирует выбранную калибровку из открытой прошивки в отдельный файл экспорта. [Строка состояния](ctp321.pdf#page=6) · [Команда экспорта](ctp321.pdf#page=5)

## Числовые представления в редакторе

В `0738` для обычных числовых представлений значение вычисляется как `(raw − смещение) × множитель / делитель`. Смещения от начала тела записи приведены ниже. Редактор различает знаковый байт, беззнаковый байт и little-endian слово скаляра. Специальные преобразования, для которых подтверждён только способ хранения, отображаются в сырых единицах.

| Тип | Делитель | Множитель | Смещение |
|---|---:|---:|---:|
| Число | `0x33` | `0x4B` | `0x53` |
| Кривая | `0x17C` | `0x194` | `0x19C` |
| Поверхность | `0x2B0` | `0x2C8` | `0x2D0` |

У поверхности с режимом `0` по смещению `0x2AE` поле по `0x275` задаёт маску ячейки. Например, две записи по `0x63D3` имеют маски `0x03` и `0x04`. Правка через вторую запись меняет бит 2 и сохраняет остальные биты. При сопоставлении 0923 эти свойства берутся из карты 0738.

### Кривые подачи топлива при пуске

На скриншотах ChipTuningPRO для штатного L19 обе оси температуры идут от −40 до 150 °C с шагом 5 °C. Асинхронная подача по `0x7152` имеет множитель `1.4222` мг/цикл на единицу сырого байта. Для малой подачи по `0x710B` множитель `2.84439215`. Подписанные точки на скриншотах совпадают после округления до целого. Например, асинхронная подача при −10 °C равна `101 × 1.4222 ≈ 144` мг/цикл, малая при −40 °C равна `113 × 2.84439215 ≈ 321` мг/цикл. Полная шкала по Y соответствует диапазону кодов от 0 до 255.

## Пороги вентилятора в L19

Два независимых изменения в Chip Tuning Pro 3.21.0738 подтверждают адреса порогов. У обоих параметров кодирование `T [°C] = uint8 − 40`. Для включения оно даёт весь указанный редактором диапазон от −40 до 215 °C.

| Параметр | Адрес CODE | Исходное значение | Новое значение | Файл опыта |
|---|---|---|---|---|
| Отключение вентилятора | `0x60C7` | `0x8A` = 98 °C | `0xBE` = 150 °C | `J5v05l19-fan-test.bin` |
| Включение вентилятора | `0x60C8` | `0x8D` = 101 °C | `0x52` = 42 °C | `J5v05l19-fan-test.bin.bak` |

В штатном L19 соседние ветви с `0x4B2F` и `0x4B38` читают эти байты через `MOVC A,@A+DPTR`. В обычной ветви сравнения код использует верхний порог, когда вентилятор выключен, и нижний, когда он уже включён. Температура сравнивается с порогом как беззнаковое значение. В I02 то же сравнение читает те же адреса с `0x2F7C` и `0x2F85`. Его штатные значения дают 101 °C на отключение и 105 °C на включение по той же формуле. В копии no-sec оба порога исходные.

Обычная карта и `_f` сборки `0738` содержат одинаковые записи обоих порогов. Остальные изменения BIN описаны в [разборе сохранения](firmware.md#сохранение-в-chip-tuning-pro-321).

## Как привязать калибровку к коду

1. Зафиксировать SHA-256 исходного BIN, карту, версию редактора и название параметра. Для первого опыта брать одну константу, у которой понятны единицы и диапазон, например порог температуры, наблюдаемый в диагностике.
2. В копии BIN изменить только этот параметр. Найти меняющиеся смещения и отделить служебные изменения образа. Повторить с другим значением, в том числе с переходом через границу одного байта, если диапазон позволяет.
3. Для таблицы по очереди менять соседние элементы и узлы оси. Определить размер элемента, порядок байтов, порядок осей и шаг строк. Найти обращения из кода к адресу таблицы, определить насыщение, округление и интерполяцию.
4. Записывать в открытое описание имя, профиль ЭБУ и SHA-256 образа, адрес и адресное пространство, тип и знаковость, размеры, оси, единицы, преобразование сырого значения, границы и подтверждающий эксперимент. Константа, график и таблица нуждаются в явном описании типов.
5. Проверить формулу по нескольким точкам редактора, переоткрытию изменённой копии и ожидаемому поведению на стенде. Для открытой прошивки хранить собственные определения отдельно для каждого профиля, с версионированием структуры.
