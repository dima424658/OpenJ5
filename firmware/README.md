# Сборка J5V05L19 из исходного кода

Штатный образ для Январь 5.1 `2112-1411020-41` и C509-L собирается в плоский файл `build/J5v05l19.bin`. Все 65 536 байт образа собираются из исходников Си и привязанных к ним правил SDCC. Для проверки и экспорта BIN используется Python 3. На macOS инструменты SDCC можно установить командой `brew install sdcc`. Проверено с SDCC 4.6.0 и GNU Make 3.81. [Руководство SDCC](https://sdcc.sourceforge.net/doc/sdccman.pdf)

Из корня репозитория:

```sh
make -C firmware
make -C firmware verify
```

Первая команда компилирует исходники через `sdcc`, линкует их через `sdld` и конвертирует Intel HEX в BIN. Конвертер проверяет контрольные суммы записей, уникальность адресов и покрытие всех 65 536 байт. В `firmware/build/` также сохраняются Intel HEX, листинги компилятора и карта линковки.

Вторая команда сверяет сборку с [эталонным BIN](../bins/J5v05l19.bin), проверяет положение векторов и процедур по карте линковки, сумму Flash и обе суммы областей калибровок. При расхождении она показывает первое несовпадающее смещение. Для отдельной копии эталона можно передать `REFERENCE=/путь/к/J5v05l19.bin`. Ожидаемый SHA‑256 приведён в [карте памяти](../docs/firmware.md#идентификация).

## Как устроена реконструкция

Назначение алгоритмов и калибровок сопоставлено с руководством CTP 3.21, картами J5 и обращениями из штатного кода. В карте символов указаны адреса, соответствия картам и места, где назначение ещё уточняется. [Руководство CTP 3.21](../docs/ctp321.pdf) · [Карта символов](docs/symbols.md)

Правила `.peep` сохраняют соглашения о регистрах C509-L, форму ветвлений и точную раскладку инструкций. В одном месте две точки входа используют общие байты инструкций. Это перекрытие сохраняется правилом для процедур записи диагностических записей. [Карта символов](docs/symbols.md)

## Структура файлов

- Переходы таблицы векторов собираются из `src/target/c509/entry_vector.c`, пустые обработчики прерываний из `src/target/c509/unused_vector.c`.
- Билинейная интерполяция таблиц в CODE и XDATA собирается из `src/math/bilinear_interp.c`, одномерная интерполяция из `src/math/interp_curve_q4.c` и `src/math/interp_curve_u8.c`.

| Каталог | Содержимое |
|---|---|
| `src/engine/` | Управление двигателем, расчёты топлива и воздуха, зажигание и диагностика пропусков |
| `src/calibration/` | Калибровки, таблицы и паспорт прошивки |
| `src/startup/`, `src/storage/` | Запуск, выключение, состояние в RAM и EEPROM |
| `src/diagnostics/`, `src/service/`, `src/monitor/` | Диагностические команды, служебный обмен и монитор |
| `src/math/`, `src/target/c509/`, `src/include/` | Арифметика, код C509-L, общие заголовки |
| `src/rom/` | Фиксированная раскладка и заполнение образа |
| `mk/`, `scripts/`, `docs/` | Размещение секций, настройки сборки, проверка образа и карта символов |

Файл `src/rom/rom_layout.c` хранит нулевое заполнение и 62 байта региона калибровок с ещё не подтверждённым назначением. Абсолютные адреса и размеры проверяются по карте линковки.

Правила `.peep` лежат рядом с соответствующими процедурами. Общие правила для нескольких подсистем расположены в `src/target/c509/` или `src/engine/`. В `mk/sources.mk` собраны соответствия между адресами секций и исходниками. Варианты, которые собираются из общих файлов с отдельными настройками, указаны в `mk/compiler.mk`. Линковщик размещает секции по исходным адресам, а `make verify` сверяет их положение и размер.

Для процедуры по `0xA429` SDCC дополнительно использует `src/math/accumulator.peep`. Эти правила выбирают короткие инструкции для операций над регистром аккумулятора. Условие, преобразование значения и порядок операций заданы в C.

В арифметических процедурах из `src/math/minimum_u16_register_pair.c`, `src/math/negate_u16_register_pair.c` и `src/math/register_pair_arithmetic.c` входы и выходы следуют соглашению штатной прошивки. Локальные правила `src/target/c509/stock_registers.peep` преобразуют обращения к операндам C в инструкции для активного в момент вызова банка регистров. Эти файлы собираются с `--no-peep`, поскольку встроенные правила SDCC могут удалить запись в регистр результата, если штатный вызывающий код использует соглашение, неизвестное компилятору. [Руководство SDCC](https://sdcc.sourceforge.net/doc/sdccman.pdf)

Блок расчёта координат температурной оси `src/engine/sensors/update_coolant_axis.c` встроен между двумя участками обработчика датчиков. Правила `src/engine/sensors/coolant_axis.peep` используют частное и остаток одной инструкции деления. Переход к продолжению в C компилируется в сквозное выполнение. Проверка карты линковки закрепляет адрес продолжения `0x33C2` сразу после блока.

Сборка проверена побайтовым сравнением образов на компьютере.
